サービス概要

アパレルショップ検索アプリです。

制作目的

店舗を探す際、Googleやショップサイトで住所情報を得ることはできますが、 情報を一括して調べられるようにし、目的の店舗にたどり着くまでの手間を省きたいと思い作成しました。 また、将来的に運用できること、個人的に多少なりとも知見があること、 身近で需要がありそうなサービスであることを考え、アパレルショップ検索アプリにしました。

主な機能

1. Cookieを使った検索機能

React Cookieを使用し、検索時に検索履歴を保存・表示できるようにしています。 また、検索履歴を削除することもできます。

2. Google Mapsでの店舗情報表示

Google Maps APIを使用し、店舗情報に連動したマーカーを表示しています。 店舗を選択すると、対応するマーカーと地図の表示位置も移動します。

スマートフォン版

3. Fetch APIを使った店舗情報登録

Fetch APIで郵便番号検索APIと通信し、取得した住所をフォームに反映しています。 また、検索した都道府県に対応するエリア情報をデータベースから取得し、 新しいエリアを登録する際のエリアコードにも連動させています。

Fetch APIでエリアを登録し、新しく追加したエリアも画面に反映しています。

総評

感想

作り終えて感じたのは、設計や基礎部分の理解がとても重要だということです。 作りたいものに対して、どのような技術を使うのか、データベースやデザイン、フォルダ構成をどう設計するのかを 初期段階で選定することが大切だと感じました。 開発中に技術を導入しては変更することを繰り返したため、途中から設計が噛み合わなくなり、 無駄な工程や手戻りが発生しました。 また、フレームワークを使えば、ネットの記事を参考にして機能を動かすこと自体はできますが、 独自の機能を作るには、基礎や仕組みを理解していないと思いどおりに動かせないと実感しました。 他のアプリと同様、完成を優先したため、デザインをもっと作り込めなかったことが少し心残りです。

今後の課題

TypeScriptの導入

学習コストを考えて導入を見送りましたが、型を定義することの重要性を実感しました。 今後はTypeScriptを導入したいと考えています。

不要なレンダリングの削減

一部で使用していますが、useMemoやuseCallbackを適切に活用し、 不要なレンダリングを抑えることでパフォーマンスを改善したいと考えています。

CI/CDの改善・コンテナデプロイ

本番環境は手動で構築したため、今後はコンテナを使ったデプロイに変更したいと考えています。 また、現在のGitHub Actionsではビルドとデプロイを自動化していますが、 GitHub Actions上でテストを実行できていません。 コンテナデプロイと合わせて、テストからビルド・デプロイまで自動化したいと考えています。

制作を終えて

Webデザイン制作会社に勤めていた経験もあり、そこまで苦労しないと思っていました。 しかし、働きながら制作を進める中で学ぶことが非常に多く、難しさ以上に時間が足りないと感じました。 AWSを導入した際にはインフラの知識も必要になり、サブネットマスク、CIDR、パブリックIPなどを 理解するためにも時間がかかりました。学ぶことに終わりはないと感じています。 また、技術の移り変わりがとても早いことも実感しました。 制作会社に入社した頃はjQueryがよく使われており、AngularをJavaScriptのフレームワークとして認識していましたが、 その後ReactやVueなどを学ぶようになりました。 ビルドツールについてもWebpackを学んだ後、Viteを学び直しました。 こうした経験から、感覚だけで実装するのではなく、最低限の仕組みや構造を理解したうえで開発することが 大切だと感じています。ログイン機能であればセッションやCookie、Reactであればライフサイクルなど、 基礎を理解することが重要だと思います。 もともとコードを書くことが苦ではなかったこともあり、苦労しながらも制作と学習を続けてこられてよかったです。
